# Тетради разведочного анализа

Тетрадь не является частью сервиса. Код, который нужен конвейеру, переезжает в
`backend/app/features/` или `backend/app/ml/`. Выводы переезжают в
`hackathon-gap-analysis.md`.

| Тетрадь | О чём |
|---|---|
| `00-data-guide.ipynb` | Что нам дали: файлы, колонки, типы датчиков и их смысл, ловушки ручного анализа, схема хранения под дообучение |
| `01-eda-clustering.ipynb` | Признаки поведения канала, UMAP и HDBSCAN, отбор интересных кластеров |
| `02-motion-timeline.ipynb` | Поток срабатываний датчика движения во времени: сеть целиком и отдельные каналы в четырёх масштабах |

Начинать с `00`. Она ничего не моделирует и читается за один заход.

## Как запустить

Окружение уже собрано в корне проекта.

```
uv run --python .venv/Scripts/python jupyter lab notebooks/
```

Прогнать целиком без интерфейса:

```
.venv/Scripts/python -m jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=3600 notebooks/01-eda-clustering.ipynb
```

Первый запуск считает около трёх минут. Дальше раскладка UMAP берётся из кэша, и
остаётся около минуты.

Тетрадь `02` считает около 8 секунд и в `out/` ничего не пишет.

## Что нужно на входе

- `raw_task/dataset/` с выгрузкой. Каталог в репозиторий не входит.
- `eda/out/events.parquet`. Если файла нет, тетрадь `01` соберёт его из CSV сама.
  Сборка занимает около 23 секунд и даёт 1,82 ГБ. Тетрадь `02` этот файл требует
  готовым: сама она его не собирает.

## Что получается на выходе

Каталог `notebooks/out/`, в репозиторий не входит.

| Файл | Что в нём |
|---|---|
| `channel_features.parquet` | 11 485 каналов, признаки поведения, координаты UMAP, метка кластера |
| `cluster_profile.csv` | портрет каждого кластера и его метка |
| `unit_rollup.parquet` | свод к паре «объект и пикет», то есть к единице прогноза |
| `umap_<отпечаток>.npy` | кэш раскладки |

## Воспроизводимость

Тетрадь обязана давать один и тот же ответ при каждом запуске. Она печатает два
отпечатка: входной матрицы и раскладки. Если они меняются между запусками,
что-то сломано, и выводы читать нельзя.

Мы на этом уже обожглись. Первые прогоны дали от 14 до 25 кластеров на одних и
тех же данных. Причина оказалась не в UMAP: параллельный join в DuckDB отдавал
строки в произвольном порядке, а порядок строк меняет список соседей. Лечится
`ORDER BY` в запросе признаков.

## Правила

1. Разбиение выборки при обучении только по времени. Спецификация §9. К
   кластеризации это не относится: она метку не использует.
2. Число в тексте тетради обязано быть посчитано ячейкой выше. Числа из головы
   не писать.
3. Вывод, который данные не подтвердили, удалять, а не смягчать.
