# LCT2026 — прогнозирование аварий инженерных коллекторов

Международный хакатон 2026, задача 8 (ЖКХ). Сервис предиктивной аналитики для
АО «Москоллектор»: ML-модель прогнозирования аварий и отказов оборудования,
веб-интерфейс диспетчера ОДС, модуль автоматического формирования заявок на
превентивное обслуживание и REST API.

| Путь | Что | Статус |
|---|---|---|
| `frontend/` | АРМ диспетчера ОДС: дашборд рисков, карта, журнал прогнозов, заявки | готово, работает на заглушках |
| `backend/` | REST API, модуль заявок, вход и роли | работает, одно направление считает модель |
| `ml/` | Модели по четырём направлениям прогнозирования | обучено одно: несанкционированный доступ |

Требования ТЗ в числах: горизонт прогноза не меньше 24 часов, время
формирования прогноза и задержка потока не больше 5 минут. Precision и Recall
ТЗ §9 велит вывести из качества данных. Значения 0.7 и 0.5 с сайта являются
умолчанием, цель своя у каждого направления. Разбор в
[INSIGHTS.md](INSIGHTS.md).

# Запуск фронтенда

Бэкенд для запуска **не нужен**: приложение целиком работает на встроенных
заглушках со всеми четырьмя направлениями прогнозирования.

## Что понадобится

- **Node.js 20.19+ или 22.12+** (Vite 8 более ранние версии не поддерживает).
  Проверить: `node -v`. Скачать: <https://nodejs.org>.
- **npm 10+** — ставится вместе с Node.

Git-клиент нужен только чтобы получить исходники.

## Три команды

```bash
git clone https://github.com/IIshikiII/LCT2026.git
cd LCT2026/frontend
npm install
npm run dev
```

Открыть <http://localhost:5173>.

Первая установка занимает 1–2 минуты, дев-сервер поднимается меньше секунды.

## Вход в систему

ТЗ §11 требует ролевую модель, поэтому приложение начинается с экрана входа.
Вход идёт в два шага: пароль, затем одноразовый код.

| Логин | Пароль | Роль | Что видит |
|---|---|---|---|
| `ods` | `collector` | Диспетчер ОДС | всё предприятие |
| `district` | `collector` | Диспетчер района | комплексы своего района |
| `tech` | `collector` | Техник | один комплекс, только чтение |
| `crew` | `collector` | Группа реагирования | закрывает заявки отметкой о факте |

Код второго фактора настоящий и на заглушках тоже. Первый вход каждой записи
показывает QR-код: наведите на него камеру приложения-аутентификатора, и оно
заведёт запись само.

Подойдёт любое приложение, которое умеет TOTP: Яндекс Ключ, Google
Authenticator, Microsoft Authenticator, 1Password, Bitwarden, Aegis, KeePassXC.
Формат стандартный — HMAC-SHA1, шаг 30 секунд, шесть цифр. Настольные
приложения тоже годятся: ключ живёт в приложении, а не в телефоне.

Под строкой «Камера не берёт код» лежат запасные пути: ключ для ручного ввода
и ссылка `otpauth://`.

### Панель тестового стенда

Если сервер поднят с `TEST_STAND=true`, справа от формы входа появляется список
наборов учётных записей. Набор — это четыре роли разом.

Панель отвечает на вопрос, который возникает у каждого проверяющего: какой
набор свободен. Ключ второго фактора остаётся в том приложении, где его завели,
поэтому занятый набор помечен «2FA пройдена», а кнопка внизу заводит следующий
набор — `ods-2`, `district-2` и так далее. Ненужный набор удаляется там же.

Флаг раздаёт логины и пароли любому, кто открыл страницу входа. Он для стенда,
и в промышленной установке его не включают.

Роли работают по-настоящему и на заглушках. Войдите техником — журнал, карта и
дашборд покажут только его комплекс. Кнопок у него не будет ни одной.

### Файл окружения

`npm run dev` работает сразу: значения по умолчанию зашиты в код. Если нужно
что-то поменять, скопируйте образец и правьте копию:

```bash
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
```

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VITE_USE_MOCKS` | `true` | Поднимать заглушки. `false` — ходить в реальный API |
| `VITE_API_BASE_URL` | `/api/v1` | База REST API |
| `VITE_API_DOCS_URL` | `/api/v1/docs` | Ссылка на Swagger в шапке |
| `VITE_MAP_STYLE_URL` | пусто | Внешняя подложка карты. Пусто — офлайн-стиль без обращений в сеть |

## Что смотреть в интерфейсе

| Экран | Адрес | Что показывает |
|---|---|---|
| Дашборд рисков | `/` | Счётчики по уровням и направлениям, топ-10 объектов, **соответствие метрикам ТЗ** |
| Карта объектов | `/map` | Настоящие округа Москвы, трассы коллекторов, точки по уровню риска с кластеризацией; клик открывает карточку |
| Журнал прогнозов | `/journal` | Основная рабочая таблица, фильтры, сортировка, выгрузка в CSV |
| Заявки | `/orders` | Что система создала автоматически и что с этим стало |

Все фильтры и выбранная карточка живут в адресной строке — ссылку на текущее
состояние можно просто скопировать и отправить коллеге.

### Дев-панель заглушек

Кнопка **«моки»** в правом нижнем углу (видна только при `VITE_USE_MOCKS=true`):

- **Новое направление** — добавляет направление, которого нет в базовом
  наборе. Оно само
  появляется в фильтрах, на карте и на дашборде: правок кода интерфейса для
  этого не требуется.
- **Сломать `/meta`** — сервер перестаёт отдавать описание предметной области.
  Приложение продолжает работать на запасных конфигах и честно пишет об этом
  в шапке.
- **Ошибки списков**, **медленная сеть** — проверка состояний ошибки и загрузки.

### Сценарий на две минуты

1. Дашборд: виджет «Соответствие метрикам ТЗ» — Precision и Recall рядом с
   целью направления; виджет «Конвейер расчёта» — время против 5 минут и
   горизонт против 24 часов.
2. Журнал: отфильтровать по критическому уровню, открыть строку — справа
   карточка с объяснением прогноза (вклад признаков, телеметрия, история
   объекта).
3. В карточке — плашка автоматически созданной заявки. Перейти по ней.
4. В карточке: «Взять в работу», затем «Принять решение» — назвать уровень
   критичности. Уровни «Высокий» и «Критический» создают заявку, «Низкий» и
   «Средний» закрывают прогноз без выезда.
5. Заявка: «Назначить бригаду» со сроком. Дальше выйти и войти как `crew` —
   у группы реагирования появится «Закрыть заявку» с обязательной отметкой
   «факт подтверждён на объекте». Именно из этой отметки считается качество
   модели на реальных данных.
6. Войти как `tech` и открыть журнал: тот же экран показывает один комплекс и
   ни одной кнопки.
7. Дев-панель: включить новое направление и вернуться на дашборд.

Весь сценарий проходится с клавиатуры.

## Подключение реального бэкенда

В `frontend/.env`:

```
VITE_USE_MOCKS=false
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

Правок в коде не требуется — заглушки просто не поднимаются. Контракт, которого
должен придерживаться бэкенд, описан в
[frontend/docs/02-api-contract.md](frontend/docs/02-api-contract.md).

## Если что-то не запускается

| Симптом | Причина и что делать |
|---|---|
| Экран входа не пускает | Логин и пароль из таблицы выше. Код берётся из аутентификатора: он настоящий и на заглушках тоже |
| Код не подходит | Часы телефона. Допуск ±30 секунд, включите автоматическое время |
| `Vite requires Node.js version 20.19+` | Старый Node. Обновить до 20.19+ или 22.12+ |
| `npm install` падает на сети | Корпоративный прокси. `npm config set registry https://registry.npmjs.org/` |
| Порт 5173 занят | `npm run dev -- --port 5174` |
| Пустой экран, в консоли ошибки MSW | Не создан воркер заглушек: `npx msw init public/` |
| На карте нет улиц, только округа и трассы | Так и задумано: подложка не загружается из сети. Спутник и улицы включаются через `VITE_MAP_STYLE_URL` |
| Кириллица в интерфейсе системным шрифтом | Нет доступа к Google Fonts. На работу не влияет |

## Главное архитектурное решение

Фронтенд не знает, сколько существует направлений прогнозирования и как они
называются. Он получает описание предметной области из `GET /meta` и строит
интерфейс по нему. Поэтому новое направление добавляется одним файлом в
заглушках (или одной строкой в ответе бэкенда) и появляется во всём интерфейсе
само — это проверяется тестом и показывается тумблером в дев-панели.
