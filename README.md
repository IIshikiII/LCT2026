# LCT2026: прогноз аварий в коллекторах Москвы

Сервис считает вероятность аварии на участках инженерных коллекторов на
ближайшие сутки. Диспетчер ОДС видит риски на дашборде, на карте и в журнале.
Опасный прогноз сам создаёт заявку на превентивное обслуживание.

Проект сделан на Международном хакатоне 2026, задача 8 (ЖКХ), для
АО «Москоллектор». Стенд: <https://utility-monitor.ru>.

## Как работает сервис

1. **Данные.** Загрузчик переносит выгрузку системы мониторинга СМВУ в
   Postgres. Заглушка СМВУ проигрывает неделю выгрузки как живой поток.
2. **Конвейер.** Прогон идёт раз в минуту. Для каждого направления он строит
   признаки строго до момента расчёта и считает вероятность события.
3. **Уровень риска.** Вероятность получает уровень `LOW`, `MEDIUM`, `HIGH` или
   `CRITICAL`. Границы уровней задаёт направление.
4. **Заявка.** Прогноз уровня `HIGH` или `CRITICAL` создаёт заявку на
   обслуживание.
5. **Решение человека.** Диспетчер подтверждает или отклоняет заявку. Бригада
   закрывает её отметкой «факт подтверждён на объекте».
6. **Интерфейс.** Фронтенд читает всё через REST API `/api/v1`. Список
   направлений он получает из `GET /meta`, поэтому новое направление не требует
   правки интерфейса.

Правила заявок описаны в [`backend/docs/07-auto-orders.md`](backend/docs/07-auto-orders.md),
путь прогноза и заявки со стрелками в [`docs/ARM-ODS-lifecycle.md`](docs/ARM-ODS-lifecycle.md).

## Направления прогноза

| Направление | Чем считается | Как часто | Подробности |
|---|---|---|---|
| Несанкционированный доступ | модель LightGBM на участке хода около 150 м | раз в сутки | [`ml/access/`](ml/access/README.md) |
| Риск подтопления | ансамбль бустеров на пикете, скользящий бюджет тревог | раз в сутки | [`ml/flood/`](ml/flood/README.md) |
| Пожарный риск | экспертные правила: модель не обогнала наивное правило | каждый прогон | [`ml/fire/`](ml/fire/README.md) |
| Отказ датчика | готовы метка и витрина, модели нет | — | [`ml/sensor/`](ml/sensor/README.md) |

## Итог по целям ТЗ

| Цель | Итог |
|---|---|
| Горизонт прогноза не меньше 24 часов | Выполнено. Прогноз дан на окно 24 часа |
| Прогноз формируется быстрее 5 минут | Выполнено. Прогон по всей сети со всеми направлениями идёт 132–205 с |
| Поток обрабатывается быстрее 5 минут | Выполнено на заглушке СМВУ. Задержка 38–57 с |
| Precision 0,7 и Recall 0,5 | Не достигнуто: данные не держат такого сигнала. Цель хранится на направлении, администратор её правит |
| Веб-интерфейс диспетчера | Выполнено. Дашборд, карта, журнал, заявки |
| Автоматические заявки | Выполнено |
| REST API | Выполнено. Описание OpenAPI лежит по адресу `/api/v1/docs` |
| Роли и вход | Четыре роли, пароль и одноразовый код |

Заказчик подтвердил, что 0,7 и 0,5 это значения по умолчанию. Событие редкое:
проникновение случается на участке в 0,8 % суток. Поэтому модель сравнивается с
наивным правилом «событие было вчера» при равной полноте.

- **Доступ:** точность 0,27 против 0,14 у правила.
- **Подтопление:** точность 38,5 % против 32,9 %, полнота 39,6 % против 32,6 %.

Разбор чисел лежит в ADR моделей: [`docs/adr/`](docs/adr/README.md).

## Локальный запуск

### Только интерфейс на заглушках

Сервер не нужен: заглушки держат все направления. Нужен Node.js 20.19 или
22.12 и выше.

1. Получите код:
   ```
   git clone https://github.com/IIshikiII/LCT2026.git
   cd LCT2026/frontend
   ```
2. Включите заглушки и установите зависимости:
   ```
   cp .env.example .env
   npm install
   ```
3. Запустите интерфейс:
   ```
   npm run dev
   ```
4. Откройте <http://localhost:5173>. Войдите логином `ods` и паролем
   `collector`. Код второго шага даст приложение-аутентификатор по QR-коду
   с экрана.

Остальные учётные записи и сценарий показа описаны в
[`frontend/docs/09-demo-guide.md`](frontend/docs/09-demo-guide.md).

### Сервис целиком

Нужны Docker с Compose и Node.js. На Ubuntu и macOS короткий путь даёт
`scripts/local.sh full`: сервер на синтетике из 40 объектов без шагов 5 и 6.

1. Перейдите в `backend` и скопируйте настройки:
   ```
   cd backend
   cp .env.example .env
   ```
2. Поднимите базу и API:
   ```
   docker compose up -d db api
   ```
3. Создайте таблицы:
   ```
   docker compose run --rm pipeline uv run --no-sync python -m app.cli migrate
   ```
4. Наполните базу синтетикой и учётными записями:
   ```
   docker compose run --rm pipeline uv run --no-sync python -m app.cli seed
   ```
5. Положите модели рядом с сервисом. На Ubuntu и macOS:
   ```
   mkdir -p artifacts/unauthorized_access artifacts/flood_risk
   cp ../ml/access/out/daily_model.joblib artifacts/unauthorized_access/latest.joblib
   cp ../ml/access/out/daily_metrics.json artifacts/unauthorized_access/metrics.json
   cp ../ml/flood/out/model.joblib artifacts/flood_risk/latest.joblib
   cp ../ml/flood/out/metrics.json artifacts/flood_risk/metrics.json
   cp ../ml/flood/out/pu_classifier.joblib artifacts/flood_risk/pu_classifier.joblib
   ```
   На Windows вместо `mkdir -p` и `cp` используйте `New-Item -ItemType Directory`
   и `Copy-Item`.
6. Передайте замер моделей на дашборд:
   ```
   docker compose run --rm pipeline uv run --no-sync python -m app.cli publish-metrics
   ```
7. Посчитайте прогнозы:
   ```
   docker compose run --rm pipeline uv run --no-sync python -m app.cli run-pipeline
   ```
8. Проверьте API: откройте <http://localhost:8000/healthz>.
9. В папке `frontend` создайте файл `.env`:
   ```
   VITE_USE_MOCKS=false
   VITE_API_BASE_URL=http://localhost:8000/api/v1
   ```
10. Запустите интерфейс из папки `frontend` командами `npm install` и
    `npm run dev`.

Настоящая выгрузка, поток СМВУ и конвейер по расписанию описаны в
[`backend/docs/02-local-run.md`](backend/docs/02-local-run.md). Установку на
сервер описывает [`deploy/README.md`](deploy/README.md).

### Если что-то не работает

| Что видно | Что сделать |
|---|---|
| `Vite requires Node.js version 20.19+` | Обновите Node.js |
| Код входа не подходит | Включите автоматическое время на телефоне. Допуск 30 секунд |
| Порт 5173 занят | Запустите `npm run dev -- --port 5174` |
| Интерфейс не видит API | Проверьте шаг 8 и адрес в `frontend/.env` |
| Интерфейс открыт по `127.0.0.1:5173` и не видит API | Откройте <http://localhost:5173>: сервер пускает запросы только с этого адреса |
| `port is already allocated` на шаге 2 | Порт 5432 или 8000 занят, чаще всего локальным Postgres. Остановите его или поменяйте левое число в `5432:5432` в `backend/docker-compose.yml` |
| На заглушках вход отвечает ошибкой | Проверьте, что в `frontend/.env` стоит `VITE_USE_MOCKS=true` |
