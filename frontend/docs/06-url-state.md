# Состояние UI живёт в URL

Глобального стора нет: ни Zustand, ни Redux, ни контекста с фильтрами.
Серверные данные — в кэше TanStack Query, состояние интерфейса — в параметрах URL.
См. [adr/0001-no-global-store.md](adr/0001-no-global-store.md).

## Что это даёт

- Ссылку на отфильтрованный журнал с открытой карточкой можно передать коллеге,
  и он увидит ровно то же. На дежурстве это основной способ сказать «посмотри вот
  это».
- Кнопки «назад» и «вперёд» работают правильно без единой строки кода.
- Карта и журнал синхронизированы по фильтрам бесплатно: они читают одни и те же
  параметры.
- Нечего синхронизировать между экранами, нечему рассинхронизироваться.

## Параметры

| Параметр | Тип | Где действует | Пример |
|---|---|---|---|
| `direction` | повторяемый | `/journal`, `/map` | `?direction=FIRE_RISK&direction=WEAR_OUT` |
| `level` | повторяемый | `/journal`, `/map` | `?level=HIGH&level=CRITICAL` |
| `status` | повторяемый | `/journal` | `?status=NEW` |
| `district` | одиночный | `/journal`, `/map` | `?district=CAO` |
| `from` / `to` | ISO-дата | `/journal` | `?from=2026-09-01` |
| `sort` | `поле:направление` | `/journal`, `/orders` | `?sort=probability:desc` |
| `page` | число, с 1 | `/journal`, `/orders` | `?page=3` |
| `orderStatus` | повторяемый | `/orders` | `?orderStatus=AUTO_CREATED` |
| `prediction` | id | `/journal`, `/map` | `?prediction=P-0042` |
| `order` | id | `/orders`, и из карточки прогноза | `?order=WO-0117` |

Правило именования: параметр называется так же, как поле фильтра в API. Тогда
`filtersToParams()` — это почти тождественное преобразование, и лишнего слоя
маппинга нет.

## API хелперов

`src/shared/lib/urlState.ts`

```ts
// Список фильтров журнала/карты. Чтение и запись, запись сбрасывает page.
const { filters, setFilter, toggleInList, reset } = useFilters()

// Выбранная сущность в правой панели.
const [predictionId, selectPrediction] = useSelectedPrediction()
const [orderId, selectOrder] = useSelectedOrder()

// Общий низкоуровневый доступ.
const value = useParam('district')            // string | undefined
const list  = useParamList('direction')       // string[]
```

Инварианты, за которыми надо следить при правках:

1. **Смена любого фильтра сбрасывает `page` на 1.** Иначе пользователь оказывается
   на девятой странице пустой выборки.
2. **Выбор сущности (`prediction`, `order`) — это `replace: false`**, чтобы «назад»
   закрывал карточку. Смена фильтра — тоже отдельная запись в истории.
3. **Пустое значение удаляется из URL**, а не пишется как `?district=`. Иначе
   ссылки становятся нечитаемыми, а `queryKey` — нестабильным.
4. **Порядок повторяемых значений нормализуется сортировкой** перед записью.
   Иначе `?level=HIGH&level=LOW` и `?level=LOW&level=HIGH` дадут два разных ключа
   кэша и два одинаковых запроса.

Пункты 3 и 4 покрыты тестами в `src/shared/lib/urlState.test.tsx`.

## Связь с ключами кэша

`src/shared/api/queryKeys.ts` строит ключ прямо из объекта фильтров:

```ts
predictions: (f: PredictionFilters) => ['predictions', f] as const
```

Поэтому нормализация из пункта 4 — не косметика, а условие того, что кэш работает.

## Чего в URL нет

Раскрытые/свёрнутые секции, состояние ввода в форме действия, позиция карты.
Это эфемерное состояние конкретного окна, ему место в `useState`. Критерий
простой: **если состоянием осмысленно поделиться ссылкой — оно в URL, иначе нет.**
