# ADR 0001. Состояние UI в URL, глобального стора нет

Статус: принято · 2026-09-08

## Контекст

Четыре экрана делят один набор фильтров (направление, уровень, район, период) и
одну правую панель с выбранной сущностью. Стандартный рефлекс — завести Zustand
и держать фильтры там.

## Решение

Всё состояние интерфейса живёт в параметрах URL и читается через
`react-router-dom`. Серверные данные живут в кэше TanStack Query. Библиотеки
состояния в проект не добавляются.

## Последствия

Хорошее:

- ссылкой на отфильтрованный журнал с открытой карточкой можно поделиться — на
  дежурстве это основной способ передать контекст коллеге;
- «назад» и «вперёд» работают без единой строки кода;
- карта и журнал синхронизированы по фильтрам бесплатно: они читают одни и те же
  параметры;
- нечему рассинхронизироваться и нечего гидрировать.

Плохое, с чем миримся:

- URL длинный и уродливый при мультивыборе;
- значения фильтров — строки, разбор и нормализация нужны на каждом чтении
  (собраны в `shared/lib/urlState.ts`, не размазаны);
- эфемерное состояние (раскрытая секция, ввод в форме) всё равно живёт в
  `useState` — то есть источник состояния не один, а два. Граница проведена
  явно: делиться ссылкой осмысленно → URL, иначе `useState`.

## Альтернативы

Zustand — отвергнут: добавляет второй источник правды рядом с URL, который всё
равно нужен ради шаринга ссылок. Контекст с фильтрами — то же самое плюс
перерисовки.
