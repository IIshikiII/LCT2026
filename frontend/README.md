# frontend

Рабочее место диспетчера ОДС: дашборд рисков, карта объектов, журнал прогнозов,
заявки. Vite, React и TypeScript. Приложение работает без сервера на заглушках
из `src/mocks/`.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
```

Переход на настоящий API задают две строки в `.env`:

```
VITE_USE_MOCKS=false
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run typecheck` | Только проверка типов |
| `npm run lint` | oxlint |
| `npm test` | Тесты Vitest, один прогон |

## Главное правило

Фронтенд не знает, какие направления прогноза существуют. Он строит фильтры,
карту и дашборд по ответу `GET /meta`. Тест `src/architecture.test.ts` падает на
типе-перечислении кодов направлений и на доменных словах вне `src/mocks/`.

Документация начинается с [`docs/README.md`](docs/README.md). Сценарий показа
лежит в [`docs/09-demo-guide.md`](docs/09-demo-guide.md).

## Дальнейшие шаги развития проекта

Построить трассу по номерам пикетов вместо условной схемы и перенять термины
заказчика: «каналы данных», «квитирование». Показать контекст срока заявки и
действующий мьют с возможностью снять его досрочно.
