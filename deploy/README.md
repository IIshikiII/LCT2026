# Развёртывание на Ubuntu 22.04

Три скрипта и один файл настроек. Всё запускается обычным пользователем с
`sudo`, не из-под root.

| Файл | Что делает |
|---|---|
| [config.sh](config.sh) | Настройки и общие помощники. Правится только он |
| [install.sh](install.sh) | Полная установка: Docker, база, API, статика, nginx, сертификат |
| [update.sh](update.sh) | Выкладка новой версии на уже развёрнутый сервер |
| [backend.sh](backend.sh) | Часть про бэкенд: Docker, модель, миграции, посев |
| [inspect.sh](inspect.sh) | Показывает, что на сервере сейчас |

## Первый раз

```bash
git clone git@github.com:IIshikiII/LCT2026.git
cd LCT2026
bash deploy/install.sh
```

Скрипт идемпотентен: запускать можно сколько угодно раз.

## Дальше

```bash
bash deploy/update.sh --pull      # обновить код и выложить
bash deploy/update.sh --reset     # вернуть демонстрационные данные в начало
bash deploy/update.sh --reseed    # засеять данные заново, с потерей прежних
bash deploy/update.sh --front     # только фронтенд, бэкенд не трогать
bash deploy/update.sh --rollback  # вернуть предыдущую сборку фронтенда
bash deploy/inspect.sh            # что сейчас на сервере
```

## Что разворачивается

```
                    nginx :443
                        │
        ┌───────────────┴───────────────┐
        │                               │
   /  → /var/www/arm              /api/v1 → 127.0.0.1:8000
   статика фронтенда                  контейнер api
                                           │
                                      контейнер db
                                      Postgres 16
```

Порт API наружу не открыт: он опубликован только на петле, а снаружи виден
через nginx. Фронт ходит на `/api/v1` того же адреса, поэтому CORS не
участвует вовсе.

Реестр MLflow на стенде не поднимается. Модели читаются файлами из
`backend/artifacts/unauthorized_access/` и `backend/artifacts/flood_risk/`,
куда их кладёт выкладка из `ml/access/out/model.joblib` и
`ml/flood/out/model.joblib`.

## Настройки

Всё в [config.sh](config.sh). Что меняют чаще всего:

| Переменная | Умолчание | Смысл |
|---|---|---|
| `DOMAIN` | `utility-monitor.ru` | имя сайта |
| `REPO` | `/home/user1/LCT/LCT2026` | где лежит репозиторий |
| `DEPLOY_BACKEND` | `yes` | `no` оставит фронтенд на заглушках |
| `TEST_STAND` | `true` | панель тестовых учёток на экране входа |
| `SEED_FACILITIES` | `200` | сколько объектов сеять |
| `SERVE_MODE` | `static` | `proxy` отдаёт dev-сервер Vite |
| `BASIC_AUTH_USER` | пусто | непустой логин закрывает стенд basic-auth |

**Про `TEST_STAND`.** Флаг показывает на экране входа логины и пароли
тестовых учёток и позволяет заводить новые наборы. Он существует ради жюри и в
настоящей эксплуатации выключается. Разбор — `backend/docs/adr/0007-roles-and-auth.md`.

## Состояния, которые скрипты разбирают сами

| Что на сервере | Что делает `update.sh` |
|---|---|
| ничего не развёрнуто | передаёт управление `install.sh` |
| работает на `<IP>.nip.io` | обновляет статику и бэкенд |
| домен доехал до сервера | зовёт `install.sh` за сертификатом на домен |
| режим `proxy` | собирать нечего, объясняет почему |

## Обслуживание бэкенда

Из каталога `backend` на сервере:

```bash
sudo docker compose ps                      # что работает
sudo docker compose logs -f api             # логи API
sudo docker compose run --rm pipeline \
  uv run --no-sync python -m app.cli reset-demo    # данные в начало
sudo docker compose run --rm pipeline \
  uv run --no-sync python -m app.cli reset-keys    # снять ключи второго фактора
```

Файл `backend/.env` собирается выкладкой и остаётся на сервере. Ключ подписи
токенов в нём создаётся один раз: новый ключ при каждой выкладке снимал бы
сессии у всех, кто уже вошёл.

## Две ловушки, на которых уже обожглись

**nvm не подключается при неинтерактивном входе.** `ssh host 'bash
deploy/update.sh'` видит системный node, в Ubuntu 22.04 это v12, и сборка
падает. `ensure_node` в `config.sh` берёт свежую версию из `~/.nvm` сам.

**Членство в группе `docker` действует со следующего входа.** Поэтому все
вызовы docker в скриптах идут через `sudo`, хотя пользователь в группу и
добавляется.
