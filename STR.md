# Правила понятного технического текста на русском

Правила для английского текста лежат в `STE.md`.

## Где действуют
Правила действуют в документации, README, описаниях pull request, сообщениях об ошибках, заметках к выпуску и комментариях. Они не действуют в коде, идентификаторах и синтаксисе команд. Они не подходят для рекламы, эссе и любого текста, которому нужен авторский голос. Правила убирают авторский голос намеренно.

## Правила
СЛОВА
- Одно название для одной вещи. Не называть один предмет двумя разными словами.
- Короткое общеупотребительное слово: начать (не приступить, не инициировать), использовать (не задействовать, не утилизировать), помочь (не содействовать, не способствовать), убедиться (не обеспечить), до (не предварительно, не до момента), после (не по завершении, не впоследствии), о (не относительно, не касательно, не в отношении), получить (не приобрести), показать (не продемонстрировать), также (не дополнительно, не кроме того, не более того).
- Одно значение для одного слова. «Падать» значит двигаться вниз, а не уменьшаться.
- Без рекламных прилагательных: бесшовный, надёжный, мощный, передовой, не требующий усилий, мирового уровня, нового поколения, революционный.

ГЛАГОЛЫ
- Действительный залог. «Парсер читает файл», а не «файл читается парсером» и не «файл прочитан парсером».
- Действие называть глаголом. «Проанализировать лог», а не «провести анализ лога». «Формирует», а не «осуществляется формирование».
- Без нагромождения вспомогательных слов. Не «важно отметить, что это может помочь улучшить». Писать «это улучшает X».
- Без обособленных причастных и деепричастных оборотов. Не «парсер, прочитав файл, строит дерево» и не «файл, прочитанный парсером, лежит в кэше».
- Необособленный причастный оборот в начале предложения допустим, если определение нельзя передать иначе без сложного предложения. Пример: «Прочитанный парсером файл лежит в кэше».

ПРЕДЛОЖЕНИЯ
- Одна инструкция в предложении. Не больше 20 слов в инструкции и не больше 25 в описании.

ПУНКТУАЦИЯ
- Без точки с запятой в прозе. Писать два предложения. В коде точка с запятой допустима.
- Без тире как знака препинания. Где грамматика требует тире между подлежащим и сказуемым, писать «это»: «Пикет это контейнер оборудования».

СТРУКТУРА
- Одна тема в абзаце, не больше шести предложений.
- Шаги оформлять нумерованным списком. Один пункт содержит одно действие в повелительном наклонении.
- Условие ставить перед командой.
- Писать только запрошенный текст. Без вступления, без итогов, без заключительных фраз.

## Режимы
- Строгий: процедуры, ранбуки, тексты о безопасности, сообщения об ошибках. Применять все правила и оба ограничения длины.
- Мягкий: остальная проза (README, описания pull request, документация). Применять правила о предложениях, абзацах, залоге и глаголах. Словарь ограничивать мягче, чтобы текст читался естественно.

## Проверка перед сдачей текста
1. Есть предложение длиннее 20 слов? Разбить его.
2. Есть точка с запятой или тире как знак препинания? Убрать.
3. Есть страдательный залог при известном исполнителе? Перевести в действительный.
4. Есть обособленный причастный или деепричастный оборот либо отглагольное существительное вместо глагола? Заменить простым глаголом.
5. Одно понятие названо двумя способами? Выбрать одно название.
