# Слой API

Все эндпоинты живут под `/api/v1`. Префикс задаёт константа `API_PREFIX` в
`app/main.py`. Проверка здоровья `GET /healthz` стоит вне префикса: её читает
Docker и балансировщик, а не фронт.

## Роутеры по областям

Каталог `app/api/` держит по модулю на область экрана: `meta`, `predictions`,
`facilities`, `orders`, `metrics`, `dashboard`. Список `ROUTERS` в
`app/api/__init__.py` собирает их, а `app/main.py` монтирует под префиксом.

Добавить область — значит добавить модуль и строку в `ROUTERS`.

## Идентификатор запроса

Каждый ответ несёт заголовок `X-Request-Id`. Каждая строка лога несёт поле
`requestId`. По нему запрос собирается из логов целиком.

Идентификатор берётся из заголовка запроса, когда клиент его прислал. Так
запрос прослеживается через nginx и через фронт. Иначе сервер создаёт свой.

Значение живёт в `ContextVar` в `app/request_context.py`. Форматтер лога читает
его сам, поэтому передавать идентификатор через аргументы не нужно.

## Строка доступа

Промежуточный слой пишет одну строку на запрос: метод, путь, код ответа и
длительность в миллисекундах.

Собственная строка доступа uvicorn выключена флагом `--no-access-log` в
`Dockerfile.api`. Иначе в одном потоке идут два формата: наш JSON и обычный
текст uvicorn.

## Ошибки

Тело ответа при ошибке — всегда `{"detail": "..."}`. Коды: 400, 404, 409, 422.

Фронт тело не читает. Любой код от 400 и выше он показывает как ошибку с
кнопкой повтора. Текст нужен человеку при отладке, поэтому он должен быть
осмысленным.

Необработанное исключение даёт 500 с общим текстом. Трассировка уходит в лог
вместе с `requestId`, а клиенту не отдаётся: внутренности сервиса наружу не
уходят. Обработчик стоит в `app/errors.py`.
