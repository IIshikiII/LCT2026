# Плагин направления и реестр версий

Документ отвечает на один вопрос: как подключить модель к сервису. Выбор
модели, разведочный анализ и кросс-валидация в нём не описаны. Это работа
команды ML, и каркас в неё не вмешивается.

Метки и метрики лежат в [06-labels-and-metrics.md](06-labels-and-metrics.md).
Прочитайте тот документ первым: он говорит, чему модель учится.

## Что уже стоит

| Файл | Что держит |
|---|---|
| `app/ml/protocol.py` | протокол предиктора, `FeatureContext`, `Window`, `Block` |
| `app/ml/registry.py` | реестр предикторов, поиск плагинов, список пропусков |
| `app/ml/tracking.py` | `log_run` и `load_model`, единственный знающий про MLflow |
| `app/ml/plugins/` | каталог плагинов: `unauthorized_access.py`, `flood_risk.py` |
| `app/features/` | реестр признаков и построители по направлениям |

Обучены два направления: несанкционированный доступ (ADR 0001–0004) и риск
подтопления (ADR 0012, 0013). Пожарный риск работает на экспертных правилах
(ADR 0016). Отказ датчика прогнозов не даёт.

Плагин может держать четыре необязательных метода. Конвейер зовёт их через
`app.ml.protocol.prepare`, `level_bands`, `own_level` и `own_summary`:

- `prepare(conn, at)` — один раз перед обходом объектов. Подтопление
  размечает в нём сутки «вода или проверка».
- `level_bands(conn, at, fresh)` — после расчёта всех объектов, до записи.
  Отдаёт границы уровней на этот прогон или `None`. Подтопление ставит в нём
  HIGH скользящим бюджетом тревог.
- `level(features, probability)` — уровень от плагина. Пожарный риск ставит
  уровень правилами по совпадению признаков, вероятность у него уровнем не
  управляет.
- `summary(features, probability)` — строка прогноза от плагина вместо
  «вероятность N %». Пожарный риск пишет в ней совпавшие признаки.

## Как подключить направление

1. Положите файл `app/ml/plugins/<код в нижнем регистре>.py`.
2. Реализуйте пять методов протокола.
3. Вызовите `register(...)` на уровне модуля.
4. Проверьте, что запись направления есть в `app/meta/directions.py`.

Реестр находит файл сам. Списка модулей нет нигде, править конвейер не надо.

```python
from app.ml import Block, FeatureContext, FeatureVector, Window, register


class SensorFailure:
    code = "SENSOR_FAILURE"

    def build_features(self, ctx: FeatureContext) -> FeatureVector: ...

    def predict(self, features: FeatureVector) -> float: ...

    def explain(self, features: FeatureVector, at: datetime | None = None) -> list[Block]: ...

    def suggest_work_type(self, features: FeatureVector, probability: float) -> str: ...

    def label_rule(self, conn, facility_id: str, window: Window) -> bool: ...

    # Необязательный метод. Без него направление считается на каждом объекте.
    def applies(self, conn, facility_id: str) -> bool: ...


register(SensorFailure())
```

Метод `applies` нужен направлению, модель которого училась не на всех
объектах. Подтопление училось на единицах с насосом или датчиком затопления,
поэтому на объекте без них оно отвечает «нет», и конвейер объект пропускает.
Проверку делает функция `app.ml.protocol.applies`: метода нет значит «да».

## Что плагин знает о направлении

Только свой код. Подпись, горизонт, типы работ, пороги автозаявки и список
причин держит реестр `app/meta/directions.py`.

Спецификация §7 перечисляет `label` и `min_horizon_hours` среди полей плагина.
Каркас от этого отступает намеренно. Подпись направления нужна процессу `api`,
который ни одной модели не видит. Вторая копия подписи разошлась бы с реестром
на первой же правке.

Следствие для метода `suggest_work_type`: он обязан вернуть строку из
`Direction.work_types`. Тот же список видит диспетчер в форме заявки.

## Объяснение прогноза

Метод `explain` отдаёт блоки карточки диспетчера. Конвейер не публикует прогноз
без блока `factors` и без блока `timeseries`. Направление доступа отдаёт третий
блок, `timeline`.

### Вес фактора

Блок `factors` держит вес каждого признака в диапазоне от минус 1 до 1. Модель
даёт вклад в логарифме шансов, и этот вклад ничем не ограничен. Правило
приведения одно на все направления:

```
r = exp(вклад в логите)
вес = (r - 1) / (r + 1)
```

Величина `r` показывает, во сколько раз признак умножает шанс события. Вес
читается как относительная поправка шанса. Признак удваивает шанс значит вес
равен 0,33. Признак утраивает шанс значит вес равен 0,5. Признак делит шанс
надвое значит вес равен минус 0,33.

Правило держит четыре свойства. Знак сохраняется. Порядок сохраняется, потому
что функция строго возрастает. Значение всегда лежит внутри диапазона и никогда
не упирается в границу. Масштаб один во всех карточках и не зависит ни от
набора признаков строки, ни от переобучения модели.

### Почему сумма весов не равна вероятности

Диспетчер видит шесть или семнадцать полос и складывает их глазом. Сумма не
сойдётся с вероятностью прогноза, и это не ошибка. Причин две.

1. **Вклады складываются в логарифме шансов, а не в вероятности.** Вероятность
   равна `сигмоида(фон + сумма вкладов)`. Фон это средний риск направления, и
   он в блоке не показан: это точка отсчёта, а не фактор.
2. **Вес это нелинейная функция вклада.** Приведение к диапазону гнёт шкалу,
   поэтому веса не складываются даже между собой.

Полосы отвечают на вопрос «что двигало прогноз и в какую сторону». На вопрос
«из чего сложилось число» они не отвечают.

### Момент расчёта

Аргумент `at` необязателен. Он называет момент, на который построены признаки.
Блоки `timeseries` и `timeline` ставят на ось абсолютное время, а вектор
признаков момента не держит: он держит только смещения вида «часов с последней
тревоги».

Конвейер передаёт `ctx.at`. Повторный разбор старого прогноза передаёт
`prediction.computed_at`. Без аргумента метод берёт текущее время, и тогда ось
старого прогноза уезжает на возраст этого прогноза.

## Направление без предиктора

Это законное состояние, а не отказ. Направление «Риск подтопления» его и
занимает: оно выключено по умолчанию и предиктора не имеет. Спецификация §13.

- `registry.active()` пропускает такое направление молча.
- `registry.missing()` отдаёт его код. Прогон конвейера пишет список в лог.

Пустой результат по направлению обязан быть видимым решением. Молчаливая
пропажа направления из выдачи — дефект.

## Два запрета, которые стоят метрик

**Признак после момента расчёта.** Поле `ctx.at` называет момент расчёта.
Данные с меткой времени после него в признак не попадают. Утечка поднимает
Precision и Recall на отложенной выборке и роняет модель в работе.

**Случайное разбиение выборки.** Обучение делит данные только по времени:
train на прошлом, test на будущем. Спецификация §9.

## Реестр версий моделей

Функции `log_run` и `load_model` из `app/ml/tracking.py`. Больше никакой модуль
`mlflow` не импортирует. Замена реестра стоит одного файла.

```python
from app.ml import load_model, log_run

log_run(
    "SENSOR_FAILURE", params={"depth": 6}, metrics={"precision": 0.81}, model=model, version="7"
)
model = load_model("SENSOR_FAILURE")
```

Недоступный сервер трекинга прогон не останавливает.

1. `log_run` всегда пишет копию модели в `ARTIFACTS_DIR`, до обращения к
   серверу. Затем пробует записать прогон и отдаёт None при отказе.
2. `load_model` берёт модель из реестра. Если реестр не ответил, берёт файл.
3. Файл читается через `joblib`, модель из реестра через `mlflow.pyfunc`.
   Оба способа не зависят от библиотеки обучения.

Выбор файла, когда версию не назвали: сначала `latest`, затем наибольший
числовой номер, затем самый свежий по времени правки. Время правки стоит
последним, потому что две записи одной секунды оно не различает.

## Разведочный анализ

Набор зависимостей `research` не входит ни в один образ сервиса.

```
docker compose --profile tools up research
```

JupyterLab поднимается на `http://localhost:8888`, корень лежит в
`backend/notebooks/`. Токена нет, порт открыт только на петлевом интерфейсе.

В наборе стоят pandas, matplotlib, seaborn, jupyterlab, scikit-learn, клиент
MLflow и три бустинга: CatBoost, LightGBM, XGBoost. Правила выбора между ними
лежат в [01-dependencies.md](01-dependencies.md).

Тетрадь не является частью сервиса. Код, который нужен конвейеру, переезжает в
`app/ml/` или `app/features/`. Выводы переезжают в `docs/`.
