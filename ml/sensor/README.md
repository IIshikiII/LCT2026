# ml/sensor — направление «отказ датчика»

Второе направление прогнозирования. Готовы витрина и метка. Признаков, модели,
порога и плагина бэкенда пока нет.

Папка отвечает на один вопрос: переносится ли порядок работы направления с
`ml/access` на новое направление. Ответ да. Оба скрипта повторяют скрипты
доступа и отличаются только списком значений. Расчёт базы и наивной планки взят
из `ml/access/target_stats.py` без единой правки.

Метка та же по форме, что у доступа: единица «объект, галерея, пикет» имеет
тревогу направления в окне (t, t + 24 ч]. Определение метки доступа лежит в
`backend/docs/adr/0001-access-target.md` и читается здесь как образец.

## Файлы

| Файл | Что делает |
|---|---|
| `01_dataset.py` | Отбирает из `eda/out/events.parquet` тревоги отказа по семи значениям таблицы `dirmap` скрипта `eda/05_feasibility.py`. Сводит их к единице «объект, галерея, пикет» по часам. Исключает объект 5343 за 2020 и 2021 годы. Результат: `out/sensor_hourly.parquet`, `out/sensor_units.parquet`. |
| `02_target.py` | Меряет базу и наивную планку на часовой и на суточной сетке. Результат: `out/target_stats.json`. |
| `out/` | Данные скриптов. В git попадает только `target_stats.json`: файлы `*.parquet` исключены правилом `.gitignore`. |

## Запуск

Скрипты запускать через `.venv` корня репозитория. Путь к интерпретатору на
Ubuntu и macOS — `.venv/bin/python`, на Windows — `.venv\Scripts\python.exe`.
Рабочей папкой должна быть `ml/sensor`: `02_target.py` берёт общий модуль по
пути относительно себя.

```
.venv/Scripts/python.exe ml/sensor/01_dataset.py
.venv/Scripts/python.exe ml/sensor/02_target.py
```

Оба скрипта идут меньше минуты.

## Значения направления

Семь значений журнала:
«Неисправен», «Обесточен», «Питание от батарей», «Батарея разряжена»,
«Много неисправных устройств», «Отключено устройство», «Не определено».

Список взят из таблицы `dirmap` в `eda/05_feasibility.py`. Та же таблица дала
строку `SENSOR_FAILURE` в `hackathon-gap-analysis.md` §A4, поэтому сверка с §A4
проверяет отбор строк, а не состав списка.

## Полученные числа

Витрина: 2 550 единиц, 5 211 каналов, 70 970 часов с тревогой, 392 818 моментов
тревоги. Период с 2019-01-02 по 2026-06-30.

Сетка «единица и час», окно 24 ч:

| Показатель | Отказ датчика | Доступ |
|---|---|---|
| Клеток | 105 862 704 | 62 570 016 |
| База | 1,132 % | 2,693 % |
| Наивная точность | 17,899 % | 26,464 % |
| Наивная полнота | 17,878 % | 26,437 % |

Числа доступа взяты из `ml/access/out/target_stats.json`. Наивная точность и
есть планка приёмки: модель отказа датчика обязана давать точность выше
17,899 % на той же сетке.

## Сверка с §A4

`01_dataset.py` печатает замер на канало-днях, то есть на сетке
`hackathon-gap-analysis.md` §A4.

| Показатель | §A4 | Замер |
|---|---|---|
| Каналов | 5 561 | 5 561 |
| Событий | 95 743 | 95 743 |
| База | 0,98 % | 0,976 % |
| Наивная точность | 14,6 % | 14,453 % |

Каналы и события совпадают точно, доли расходятся на 1 %. Таблица §A4 по
направлению `SENSOR_FAILURE` цела.

Числа §A4 на витрину модели не переносятся, и это ожидаемо: там сетка
«канал и сутки», здесь «единица и час». Единица объединяет каналы одного пикета
и поднимает и базу, и планку. То же расхождение уже разобрано по доступу в
`backend/docs/adr/0001-access-target.md`.

Исключение объекта 5343 за 2020 и 2021 годы не сдвинуло замер на канало-днях
совсем. `hackathon-gap-analysis.md` §1.6 говорит, что этот объект даёт 73 % всех
записей «Неисправен», но 73 % относятся к строкам журнала, а не к канало-дням.
Сетка суток схлопывает поток строк одного канала в одну клетку, и артефакт
исчезает.
