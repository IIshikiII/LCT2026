# ml/access: несанкционированный доступ

Модель даёт вероятность проникновения на участке хода в ближайшие сутки.
Участок это отрезок около 150 м вокруг узла входа: аварийного выхода, люка,
вентшахты или входной двери.

| Шаг | Скрипт | Что делает |
|---|---|---|
| 1 | `data.py` | Читает выгрузку и готовит таблицы. Работы ML в нём нет. |
| 2 | `panel.py` | Строит метку и признаки на сетке «участок и сутки». |
| 3 | `train.py` | Отбирает признаки, обучает модель, меряет её и ставит порог. |
|  | `cv.py` | Скользящая проверка по времени. Её зовут `train.py` и эксперименты. |
|  | `showcase.py` | Примеры для презентации: события, которые модель поймала, а правило пропустило. |
|  | `exp_disarm.py` | Эксперимент. Итоговую модель не меняет. |
|  | `tune.py` | Эксперимент: подбор параметров через Optuna. В работу не взят. |
|  | `test_panel.py` | Тест: признаки не видят будущее. |

Где что лежит:

- **Валидация** в `cv.py`: шесть полугодий 2023–2025, модель учится на истории
  до каждого. Первое полугодие 2026 года отложено для итогового замера.
- **Отбор признаков** в `train.py`, лестница по вкладу признака на отрезках
  `cv.py`.
- **Перебор гиперпараметров** в `tune.py` через Optuna. Он проверен и в
  работу не взят: точность в рабочей точке упала. Параметры LightGBM заданы в
  `cv.py` вручную, разбор в `DETAILS.md`.
- **Порог** в `train.py`: точка равной полноты с наивной планкой.

Сейчас модель даёт точность 0,27 при полноте 0,14. Это в 1,9 раза точнее
правила «событие было вчера». При 5 карточках в сутки модель предупреждает 116
событий из 491 за полгода. Ориентир равен 0,7 и 0,5. Половина событий приходит после
месяца тишины, и модель их не видит.

Запуск из корня репозитория, по порядку:

```
.venv/bin/python ml/access/data.py
.venv/bin/python ml/access/panel.py
.venv/bin/python ml/access/train.py
```

На Windows интерпретатор лежит в `.venv\Scripts\python.exe`. Подробности в
`DETAILS.md`.
