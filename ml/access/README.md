# ml/access — направление «несанкционированный доступ»

Модель прогнозирования для направления «несанкционированный доступ». Витрина,
метка, признаки, модель, порог и SHAP-объяснение готовы. Плагин бэкенда читает
`out/model.joblib` через `backend/app/ml/plugins/unauthorized_access.py`.

Определения и решения по числам лежат в трёх ADR:

- `backend/docs/adr/0001-access-target.md` — метка, окно 24 ч, режим охраны.
- `backend/docs/adr/0002-access-threshold.md` — порог и цена ошибки.
- `backend/docs/adr/0003-pipeline-duration.md` — время прогона конвейера.

Читать нужный ADR перед правкой скрипта, который его числа считает.

## Файлы

| Файл | Что делает |
|---|---|
| `01_dataset.py` | Отбирает из `eda/out/events.parquet` каналы доступа по значениям «Не замкнут», «Обнаружено движение», «Рычаг сдёрнут» с флагом «тревожное». Сводит их к единице «объект, галерея, пикет» по часам. Результат: `out/access_hourly.parquet`, `out/access_units.parquet`. |
| `02_target.py` | Меряет базу и наивную планку на витрине со всеми тревогами, окно 24 ч, событие как момент, схлопывание пачек, исключение объекта 5343 за 2020 и 2021 годы. Результат: `out/target_stats.json`. |
| `03_disarm.py` | Строит окна «Снято с охраны» и меряет две версии метки рядом: все тревоги доступа и только тревоги вне этих окон. Результат: `out/disarm_windows.parquet`, `out/access_hourly_armed.parquet`, `out/disarm_stats.json`. |
| `target_stats.py` | Общий расчёт базы и наивной планки. Модуль, а не скрипт: его зовут `02_target.py` и `03_disarm.py`. |
| `features.py` | Строит семнадцать признаков на момент расчёта `at`, все строго по строкам с `hour < at`, и обучающую панель с прореженными отрицательными клетками. Результат: `out/access_features.parquet`, `out/features_stats.json`. |
| `test_features.py` | Тест утечки по времени. Строит признаки, добавляет строки из будущего в каждый источник и проверяет, что ни один признак не изменился. Синтетические данные, `out/*.parquet` не читает. |
| `train.py` | Обучает LightGBM с разбиением по времени, считает Precision, Recall, PR-AUC и наивную планку на отложенной выборке, взвешивает отрицательные клетки панели весом обратным доле прореживания, считает SHAP-вклады на отложенной выборке с проверкой аддитивности. Сохраняет модель в `out/model.txt` (нативный формат LightGBM) и `out/model.joblib` (тот же бустер через `joblib.dump`, формат `backend/app/ml/tracking.py`). Результат: `out/model.txt`, `out/model.joblib`, `out/metrics.json`, `out/shap_background.json`. |
| `04_threshold.py` | Назначает порог по цене ошибки для диспетчера. Строит полную сетку отложенной выборки прямым счётом, без весов, и считает наряды в сутки, долю оправданных нарядов и долю предупреждённых проникновений на сетке порогов. Дописывает раздел `decision` в `out/metrics.json`. Запускается после `train.py`: читает границы отложенной выборки из его замера. |
| `05_calibrate.py` | Ставит изотоническую регрессию на проверочном отрезке, меряет кривую надёжности до и после на отложенной выборке, назначает границу уровня `CRITICAL` перебором порогов. Сохраняет `out/calibration.joblib`, дописывает раздел `calibration` и `decision.levels.CRITICAL` в `out/metrics.json`. Запускается после `04_threshold.py`: читает раздел `decision`. |
| `06_ablation.py` | Меряет вклад признака: обучает модель без него и сравнивает PR-AUC на отложенной выборке. Число раундов постоянное, замер идёт по трём семенам, рядом лежит размах. Дописывает раздел `ablation` в `out/metrics.json` и пишет `out/ablation.json`. Запускается после `train.py`. |
| `test_export.py` | Круговой тест `out/model.joblib`: `joblib.dump` и `joblib.load` обязаны давать ту же вероятность, что исходный бустер. Файлов модели нет значит тест пропускается, а не падает. |
| `out/` | Промежуточные и итоговые данные скриптов. В git не попадают, кроме `.gitkeep`. |

## Запуск

Все скрипты запускать через `.venv` корня репозитория. Путь к интерпретатору
на Ubuntu и macOS — `.venv/bin/python`, на Windows — `.venv\Scripts\python.exe`.

```
.venv/Scripts/python.exe ml/access/01_dataset.py
.venv/Scripts/python.exe ml/access/02_target.py
.venv/Scripts/python.exe ml/access/03_disarm.py
.venv/Scripts/python.exe ml/access/features.py
.venv/Scripts/python.exe ml/access/train.py
.venv/Scripts/python.exe ml/access/04_threshold.py
.venv/Scripts/python.exe ml/access/05_calibrate.py
.venv/Scripts/python.exe ml/access/06_ablation.py
```

Порядок запуска фиксирован. Каждый следующий скрипт читает результат
предыдущего из `out/`. `04_threshold.py` и `05_calibrate.py` дописывают в
`out/metrics.json`, поэтому повторный запуск `train.py` стирает разделы
`decision` и `calibration`: тогда оба скрипта нужно запустить снова, в этом
порядке.

Тесты идут отдельно, обычным `pytest`:

```
.venv/Scripts/python.exe -m pytest ml -q
```

`test_features.py` не требует файлов из `out/` и всегда идёт быстро.
`test_export.py` требует `out/model.txt` и `out/model.joblib` от `train.py`,
иначе пропускается.

### Модель (`train.py`)

Разбиение по времени, три отрезка отложенной выборки после обучающего:

| Отрезок | Период | Клеток | База |
|---|---|---|---|
| train | 2019-01-01 — 2025-06-29 | 52 410 384 | 0,4541 % |
| valid | 2025-07-01 — 2025-12-30 | 5 297 688 | 1,2284 % |
| test | 2026-01-01 — 2026-06-29 | 4 796 328 | 0,9438 % |

Отрицательная клетка панели получает вес `(клеток на отрезке − положительных) /
отрицательных в панели`, положительная — единицу. Вес возвращает модели
настоящую базу при обучении и точное число точности и полноты на полной
сетке при замере без пересчёта признаков по всем 62,6 млн клеток.

Замер на отложенной выборке (180 суток, взвешенная панель):

| Показатель | Модель | Наивное правило |
|---|---|---|
| PR-AUC | 0,0811 | — |
| Precision | 0,1552 (порог `max_f1`, см. ниже) | 0,1132 |
| Recall | 0,1890 (порог `max_f1`) | 0,1082 |
| Тревог в сутки | 306,25 (порог `max_f1`) | 240,48 |

`beats_naive: true`. Наивное правило — «тревога доступа была в прошлые сутки»,
оно же планка направления в ADR 0001.

SHAP: `shap.TreeExplainer` на отложенной выборке, 139 329 строк, фоновое
значение −6,17367. Проверка аддитивности: сумма вкладов плюс фон совпадает с
логитом с расхождением 5,3·10⁻¹⁴ при допуске 10⁻⁶ — нарушение останавливает
скрипт исключением.

Самые весомые признаки по суммарному приросту (`gain`, помогают отделить
тревогу вне окна охраны от остального потока):
`hours_since_last_armed_alarm`, `n_armed_alarms_168h`, `hours_since_last_alarm`,
`n_alarms_720h`, `night_share`.

### Вклад признаков (`06_ablation.py`, T35)

Признаки `n_alarms_1h`, `neighbor_channels_1h` и `has_access_sequence` давали
нулевой прирост до T35. Причина — пустые окна, а не бесполезность. Запрос
часового окна стоял на открытой нижней границе `hour > at − 1 HOUR`, а час и
точка расчёта оба стоят на границе часа: в окно не попадал ни один час.
Цепочка доступа была видна точке расчёта те же пятнадцать минут, что длится
сама, и попадала в панель 19 раз из 1 581 480. После правки окон признаки
живут на 12 426, 12 426 и 333 строках панели, и все три берёт дерево.

| Набор | PR-AUC | Вклад |
|---|---|---|
| полный | 0,081802 | — |
| без `n_alarms_1h` | 0,080862 | +0,000940 |
| без `neighbor_channels_1h` | 0,081706 | +0,000096 |
| без `has_access_sequence` | 0,081776 | +0,000026 |
| без всех трёх | 0,078528 | +0,003274 |

Каждое число это среднее трёх семян при постоянном числе раундов 213. Размах
внутри набора от 0,0018 до 0,0089, поэтому вклад одного признака меньше шума
жребия. Знак вклада одинаков у всех четырёх наборов, признаки оставлены.

Замер до починки повторяется прямо: набор без этих трёх колонок на сегодняшней
панели даёт PR-AUC 0,074514 и 5 деревьев — те же числа, что лежали в
`metrics.json` до T35, буква в букву. Это и есть доказательство, что колонки
держали ноль на каждой строке.

### Порог (`04_threshold.py`, ADR 0002)

| Показатель | Значение |
|---|---|
| Порог направления | 0,156089 |
| Граница уровня `MEDIUM` | 0,009438 (база направления) |
| Граница уровня `CRITICAL` | 0,04, см. ADR 0002 |
| Нарядов в сутки при пороге | 3,91 против 3,91 у наивного правила |
| Предупреждено проникновений | 236 из 1 755 (13,4 %) против 129 (7,4 %) у наивного правила |

Порог и границы пересчитаны после T35 на модели с починенными окнами. Порог
направления вырос с 0,035251 до 0,156089: шкала модели сдвинулась, потому что
модель набрала 213 деревьев вместо пяти. Граница `CRITICAL` 0,04 осталась от
прежней шкалы и теперь лежит ниже границы `HIGH`. Свести их — задача T37.

Правило выбора: порог держит цену ошибки не выше сегодняшней сразу по двум
счётам, нарядов в сутки и нарядов на одно предупреждённое проникновение, и
внутри этой области максимизирует число предупреждённых проникновений. Полный
разбор ступеней цены — в ADR 0002.

### Калибровка (`05_calibrate.py`, ADR 0002)

Изотоническая регрессия на проверочном отрезке. Счёт Брайера на отложенной
выборке: до калибровки 0,009255, после 0,009175. Калибровка снижает, но не
закрывает расхождение верхней полосы: причина в переносе между отрезками с
разной плотностью событий. Граница `CRITICAL` взята прямым перебором порогов,
а не калиброванным числом: доля событий не растёт выше сырого порога 0,08,
поэтому граница поставлена на наименьшем пороге перебора, 0,04. Полный разбор
— в ADR 0002, раздел «Калибровка и граница CRITICAL».

### Экспорт (`test_export.py`, T11)

Круговой путь `joblib.dump` → `joblib.load` даёт ту же вероятность, что
исходный бустер, буква в букву. Формат читает `backend/app/ml/tracking.py`.

## Известные ограничения

- Калибратор `out/calibration.joblib` не подключён к предиктору бэкенда:
  `backend/app/ml/plugins/unauthorized_access.py::predict` отдаёт сырую
  вероятность бустера, а `app/meta/catalog.py::level_for` сравнивает её с
  общими порогами уровней (0,3 / 0,55 / 0,78), едиными для всех направлений,
  а не с `decision.levels` из `metrics.json`. Граница `CRITICAL` из ADR 0002
  сейчас нигде не читается кодом бэкенда. Разбор — отдельная задача.
- `lightgbm` и `shap` живут в наборе зависимостей `ml`, перенесены из
  `research` в T29, см. `backend/docs/01-dependencies.md`.
