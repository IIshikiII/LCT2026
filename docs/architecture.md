# Архитектура и стек

## Компоненты

```
 выгрузка СМВУ ──► загрузчик (ingest) ──┐
                                        ▼
 заглушка СМВУ ──► POST /stream/events ─► Postgres ◄── конвейер (scheduler, раз в минуту)
                                        │              плагины направлений:
                                        │              модели LightGBM и правила пожара
                                        ▼
                                 REST API /api/v1 (FastAPI)
                                        │
                                        ▼
                   интерфейс диспетчера (React, статика за nginx)
```

| Компонент | Где лежит | Что делает |
|---|---|---|
| Загрузчик | `backend/app/ingest/` | Читает выгрузку через DuckDB и пишет Postgres через `COPY`. Сдвигает время на целые недели к сегодняшнему дню |
| Заглушка СМВУ | `backend/app/stub/` | Проигрывает неделю выгрузки как поток и шлёт его пачками раз в 2 секунды |
| Конвейер | `backend/app/pipeline/` | Раз в минуту считает прогнозы, уровни риска, объяснения и автозаявки |
| Плагины направлений | `backend/app/ml/plugins/` | Одно направление это один плагин: признаки, метка, модель, границы уровней |
| API | `backend/app/api/` | Отдаёт прогнозы, заявки, метрики и описание предметной области. Проверяет роль |
| Интерфейс | `frontend/src/` | Четыре экрана и карточка прогноза. Строит себя по `GET /meta` |
| Обучение | `ml/` | Скрипты меток, признаков и моделей. Готовая модель уходит в `backend/artifacts/` |

## Главные решения

1. **Направление это плагин.** Интерфейс не знает, сколько направлений
   существует. Он получает их из `GET /meta`, и новое направление не требует
   правки фронтенда. Тест `frontend/src/mocks/flexibility.test.tsx` это
   проверяет.
2. **Карточка прогноза это массив блоков.** Сервер присылает блоки
   `{ type, title, data }`, фронтенд рисует их по реестру. Неизвестный тип
   рисует запасной блок.
3. **Действия приходят с сервера.** Кнопки карточки описывает ответ API, и все
   они идут в одну ручку `POST /predictions/{id}/actions/{code}`.
4. **Ритм зависит от направления.** Доступ и подтопление обучены на расчёте в
   полночь и обновляются раз в сутки. Пожар обновляется каждым прогоном.
5. **Одна открытая карточка на объект и направление.** Свежий прогноз
   переписывает нетронутую карточку. Карточку в работе и законченную он не
   трогает, поэтому решения диспетчеров остаются в истории. На объект допустима
   одна открытая заявка (ADR 0021, ADR 0022).
6. **Сервис работает только на чтение из СМВУ.** Команды в систему заказчика он
   не шлёт.

Решения с числами и доводами лежат в ADR:
[`backend/docs/adr/`](../backend/docs/adr/) и [`frontend/docs/adr/`](../frontend/docs/adr/).

## Службы Docker

| Служба | Образ | Порт | Что делает |
|---|---|---|---|
| `db` | `postgres:16-alpine` | 5432 | База сервиса и тестовая база `arm_test` |
| `api` | `Dockerfile.api` | 8000 | REST API. В образе нет библиотек ML |
| `mlflow` | `Dockerfile.mlflow` | 5000 | Реестр версий моделей |
| `pipeline` | `Dockerfile.pipeline` | — | Разовые команды: миграции, посев, прогон |
| `scheduler` | `Dockerfile.pipeline` | — | Конвейер раз в минуту |
| `smvu-stub` | `Dockerfile.pipeline` | — | Заглушка потока СМВУ |
| `research` | `Dockerfile.research` | 8888 | JupyterLab для разведочного анализа |
| `dev` | `Dockerfile.dev` | — | Тесты и линтеры |

Все порты открыты только на `127.0.0.1`. На сервере наружу смотрит только
nginx.

## Роли и безопасность

Вход идёт в два шага: пароль, затем одноразовый код TOTP. Четыре роли: техник,
диспетчер района, диспетчер ОДС и группа реагирования. Роль задаёт, какие
объекты человек видит и какие действия выполняет. Порядок входа и таблица прав
лежат в [`backend/docs/09-auth.md`](../backend/docs/09-auth.md).
