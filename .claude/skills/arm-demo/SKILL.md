# Демо и приёмка АРМ диспетчера ОДС

## Что показать жюри (по описанию итогового продукта из ТЗ)

1. **Дашборд рисков** — счётчики по уровням и направлениям, топ-10 объектов.
2. **Виджет соответствия метрикам ТЗ** — Precision против 0.7, Recall против 0.5
   по каждому направлению; время расчёта против 5 мин; минимальный горизонт
   против 24 ч. Существует, чтобы жюри увидело метрики, не открывая ноутбук с
   моделью.
3. **Карта объектов** — точки по уровню риска, фильтр, клик → карточка.
4. **Журнал прогнозов** — таблица, фильтры в URL, экспорт CSV, колонка горизонта.
5. **Карточка прогноза** — блок объяснения (вклад факторов), телеметрия,
   история объекта.
6. **Полный цикл**: прогноз → система создала черновик заявки → диспетчер
   подтверждает → закрытие заявки с обязательной отметкой «прогноз
   подтвердился / не подтвердился». Эта отметка — источник честных Precision и
   Recall на реальных данных.
7. **Ссылка на Swagger** в шапке — четвёртый пункт продукта (REST API).

Прогоняется целиком с клавиатуры.

## Проверка перед показом

- `VITE_USE_MOCKS=true`, бэкенд не нужен.
- `npm run typecheck`, `npm run lint`, `npm test` — чисто.
- Сид детерминированный, данные на месте, в топ-рисках есть критические.
- Кнопка «сломать `/meta`» → приложение поднимается на запасных конфигах.
- Ссылка на отфильтрованный журнал с открытой карточкой восстанавливает
  состояние.

## Критерии приёмки (spec §12)

- Работает целиком на моках.
- Новое направление в мок `/meta` появляется в фильтрах, на карте и дашборде
  без правок кода.
- Блок неизвестного типа рисуется запасным рендерером, экран не падает.
- Действие с неизвестным кодом рисуется обычной кнопкой с формой по полям.
- Поломанный `/meta` не мешает приложению подняться.
- Ни одного `switch` по коду направления во всём коде.
