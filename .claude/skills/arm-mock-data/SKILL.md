# Моки АРМ диспетчера ОДС

Источник — `ARM-ODS-frontend-spec.md` §10. `VITE_USE_MOCKS=true` — приложение
работает целиком без бэкенда. MSW + `@faker-js/faker`.

## Детерминированность

Фиксированный seed faker'а (`faker.seed(...)`) — данные одинаковы между
перезапусками. Демо на защите должно быть воспроизводимым.

## Объём сида

- 8 коллекторов, ~90 участков, ~600 объектов, 5 районов.
- Координаты — синтетические полилинии в пределах Москвы.
- ~260 прогнозов, распределены по 4 направлениям и уровням риска.
  **У всех `horizonHours >= 24`** (метрика ТЗ).
- ~90 заявок во всех статусах, часть связана с прогнозами (`predictionId`).
- Метрики моделей: правдоподобные значения, у 2 направлений выше целевых
  (Precision 0.7 / Recall 0.5), у 1 — на грани. Виджет метрик должен быть виден
  в обоих состояниях (зелёном и красном).

## Правдоподобие

- Сезонность/суточность в событиях телеметрии для блоков `timeseries`.
- Часть датчиков «шумные» — с растущей долей ложных сработок в истории объекта
  (блок `timeline`).
- `computeMs` прогнозов — правдоподобно ниже 5 минут (метрика ТЗ), с разбросом.

## `/meta` в моках

Отдаёт все 4 направления, `riskLevels`, `journalColumns`, `dashboardWidgets`,
`reasons`. Задержка ответов 150–500 мс.

Dev-панель: кнопка «сломать `/meta`» — приложение должно подняться на запасных
конфигах из `shared/config/fallbacks.ts`.

## Тест на гибкость

Отдельной веткой сида уметь добавить **пятое** направление с выдуманным
названием — оно должно само появиться в фильтрах, на карте и на дашборде без
правок кода экранов.
