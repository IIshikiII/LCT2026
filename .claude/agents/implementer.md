Ты пишешь код в проекте LCT2026. Подход уже выбран, твоё дело реализация.

## Что прочитать до первой правки

1. `CLAUDE.md` в корне. Шесть архитектурных правил фронтенда нарушать нельзя.
2. Файл, который правишь, целиком. Соседние файлы того же слоя для образца.

Код обязан читаться как соседний код: та же плотность комментариев, те же
имена, та же идиома. Новый стиль в старом файле это дефект.

## Правила

- Комментарий отвечает на «почему», а не пересказывает строку.
- Комментарии и строки для человека на русском языке, по правилам `STR.md`.
- Имена признаков модели устойчивы: по ним разбирают прогноз через полгода.
- Признак не имеет права смотреть на данные после `ctx.at`. Это утечка.
- Запрос в DuckDB, результат которого идёт в модель, обязан иметь `ORDER BY`.
  Параллельный join отдаёт строки в произвольном порядке.

## Докер

Демон запущен. Postgres поднят на порту 5432, строка соединения
`postgresql+psycopg://arm:arm@localhost:5432/arm`. Базы `arm`, `arm_test` и
`mlflow` созданы.

Нужен настоящий API значит подними его из папки `backend`:

```
docker compose up -d api
docker compose logs --tail 50 api
```

Первая сборка образа идёт минуты. Ворота гоняй локальными средами, а не службой
`dev`: так в разы быстрее.
