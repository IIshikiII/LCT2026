# Автономный цикл

Папка держит обвязку, которая даёт Claude Code работать без человека заданное
число часов. Цель цикла лежит в `GOAL.md`, план работ в `BACKLOG.md`.

## Запуск

```
powershell -ExecutionPolicy Bypass -File loop\preflight.ps1
powershell -ExecutionPolicy Bypass -File loop\run-loop.ps1 -Hours 8
```

Первая команда проверяет среду и поднимает Postgres. Вторая запускает цикл.

Остановить цикл: создать файл `loop\STOP`.

```
New-Item loop\STOP
```

Так цикл даёт текущей итерации закоммититься и выходит сам.

**Ctrl+C обрывает итерацию посреди работы.** Деньги за неё потрачены, а
несохранённая правка теряется. В логе такой обрыв виден по полю
`terminal_reason` со значением `aborted_tools` или `aborted_streaming`.

Отдельная ловушка: в Windows Terminal `Ctrl+C` без выделенного текста не
копирует, а прерывает. Копировать вывод цикла лучше мышью или `Ctrl+Shift+C`.
Надёжнее всего запускать цикл в отдельном окне, в которое ты не печатаешь.

## Что происходит за один проход

1. Драйвер берёт первую незакрытую задачу из `BACKLOG.md`.
2. Тег строки выбирает модель: `opus` для решений, `sonnet` для механики.
3. Драйвер запускает `claude -p` с промптом `prompts\iteration.md`.
4. Итерация делает одну задачу, прогоняет ворота и коммитит.
5. Драйвер прогоняет ворота сам и пишет `GATES.md`.
6. Ворота красные значит следующая итерация идёт по `prompts\repair.md`.
7. Задачи кончились значит следующая итерация идёт по `prompts\replan.md`.

Состояние живёт в файлах, а не в сессии. Каждая итерация это новый процесс с
чистым контекстом. Поэтому цикл переживает сброс лимита, падение процесса и
переполнение окна.

## Ключи драйвера

| Ключ | Умолчание | Что делает |
|---|---|---|
| `-Hours` | 8 | бюджет рабочего времени, ожидание сброса лимита не считается |
| `-HardStopHours` | 20 | предел по стенным часам, защита от вечного ожидания |
| `-StopAt` | нет | остановиться в названный час, например `08:00` |
| `-MaxBudgetUsd` | 0 | предел трат, 0 снимает предел |
| `-MaxIterations` | 400 | предел числа проходов |
| `-DefaultModel` | opus | модель для задач без тега |
| `-FullGates` | выкл | гонять все ворота, а не только затронутые |
| `-AllowWeb` | выкл | разрешить агенту сеть |
| `-AllowMachineSleep` | выкл | не удерживать машину от сна |
| `-Once` | выкл | один проход и выход, для дымовой проверки |
| `-DryRun` | выкл | показать следующую задачу и выйти |

Ключ `-HardStopHours` ставить тесно нельзя. Один сброс лимита стоит до пяти
часов ожидания, и предел в семь часов обрывает цикл после первого же. Нужен
конец в известный час значит бери `-StopAt`, а `-HardStopHours` оставляй
умолчанием.

## Сон машины

Цикл просит Windows не засыпать, пока работает. Без этого ожидание сброса
лимита однажды закончилось плохо: цикл лёг спать до 04:12, через семнадцать
минут система ушла в ждущий режим по таймауту простоя и заморозила процесс.
Он проснулся в 08:58 вместе с машиной, увидел, что предел по стенным часам
прошёл, и вышел. За ночь не сделано ничего.

Запрос идёт через `SetThreadExecutionState` и живёт только пока жив процесс.
Настройки машины он не трогает. Проверить: `powercfg /requests`.

Запрос держит систему, но не экран: монитор гаснет как обычно.

Чего запрос не умеет: он не спасёт от закрытой крышки ноутбука и от сна по
команде человека. Ноутбук на ночь оставляй открытым или поменяй действие при
закрытии крышки.

Проснулся позже назначенного значит цикл пишет в лог, на сколько минут опоздал
и что машину усыпляли.

## Сброс лимита

Драйвер определяет лимит по полю `api_error_status` ответа, а не по тексту.
Текст он тоже разбирает, но вторым: формулировки меняются, код 429 нет.

Время сброса берётся из двух форм. Метка времени вида `limit reached|1750000000`
и часы вида `resets 7:10pm`. Драйвер спит до названного момента плюс две минуты
и берёт ту же задачу снова. Задача провалом не считается: файлов никто не
тронул, поэтому ворота после отказа не гоняются.

Времени в сообщении нет значит драйвер спит 10 минут, потом 20, потом 40, потом
по часу.

Сброс лежит за пределом `-HardStopHours` значит цикл выходит сразу и пишет
причину, а не засыпает до собственной смерти.

Время сна не тратит бюджет `-Hours`. Ограничитель `-HardStopHours` его считает.

## Пустой отказ

Вызов вернул ненулевой код, ноль денег и один ход значит до модели он не дошёл.
Виновата машина или служба, а не задача. Драйвер не засчитывает такой отказ
задаче, не гоняет ворота и отступает: 2 минуты, 5, 10, 20, потом по 30. Восемь
пустых отказов подряд останавливают цикл.

Без этого правила отказ службы выглядел бы как трижды упавшая задача, и цикл
уносил бы её в `BLOCKED.txt` за четыре минуты.

## Ворота

```
powershell -ExecutionPolicy Bypass -File loop\gates.ps1
powershell -ExecutionPolicy Bypass -File loop\gates.ps1 -Scope backend
```

| Область | Что гоняет |
|---|---|
| `frontend` | typecheck, lint, vitest |
| `backend` | ruff, mypy, pytest |
| `ml` | ruff, pytest, если в `ml/` есть тесты |
| `fast` | только typecheck и lint фронтенда |
| `all` | всё |

Отчёт уходит в `GATES.md`. Первая строка говорит `PASS` или `FAIL`.

Каждые ворота идут под своим таймаутом. Зависшая проверка считается упавшей, а
её процесс снимается. Иначе один зависший `pytest` съел бы всю ночь.

Драйвер выбирает область по тому, что изменил коммит. Каждый пятый проход и
любая починка гоняют всё.

## Докер

Демон запущен, и цикл им пользуется. Preflight поднимает Postgres и ждёт, пока
служба станет здоровой.

```
cd backend
docker compose ps
docker compose up -d db
docker compose up -d api
```

Базы созданы при первом старте: `arm` рабочая, `arm_test` для тестов, `mlflow`
для реестра моделей. Строка соединения с хоста
`postgresql+psycopg://arm:arm@localhost:5432/arm`.

Ворота гоняют локальные среды, а не службу `dev`: локально это секунды, в
образе минуты. Служба `api` нужна на сквозной проверке, и первая её сборка
стоит минут.

Снос тома базы заблокирован ловушкой. Postgres без тома теряет схему и данные
синтетики, а восстановление стоит дороже, чем чистка таблиц запросом.

Список служб и правила пользования лежат в `GOAL.md`. Их читает каждая итерация.

## Ловушка опасных команд

`guard.py` стоит на `PreToolUse` и запрещает то, чего нельзя откатить: `git
push`, `git reset --hard`, `git clean`, смену ветки, удаление `raw_task/` и
`eda/out/`, снос тома базы, публикацию пакетов, скачивание кода в оболочку.

Цикл работает с обойдёнными разрешениями, поэтому ловушка это единственное, что
стоит между агентом и необратимым действием. Проверка ловушки входит в
preflight.

Ловушку ставит `settings.loop.json`. Файл собирает preflight, потому что в нём
абсолютные пути.

## Подагенты

`agents/` держит четыре описания. Preflight копирует их в `.claude/agents/`.

| Агент | Модель | Для чего |
|---|---|---|
| `implementer` | sonnet | код по готовому описанию |
| `data-analyst` | sonnet | счёт по выгрузке в DuckDB |
| `doc-writer` | sonnet | документы по правилам STE |
| `verifier` | sonnet | прогон ворот и краткий доклад |

Итерация на Opus поручает им механику. Дорогая модель тратится на выбор
подхода, разбор чисел и спорные решения.

## Файлы

| Файл | Кто пишет | Что это |
|---|---|---|
| `GOAL.md` | человек | цель и границы, читается каждой итерацией |
| `BACKLOG.md` | человек, потом цикл | план работ, формат строки менять нельзя |
| `JOURNAL.md` | цикл | что сделано, какие числа, какие решения |
| `GATES.md` | `gates.ps1` | итог последней проверки |
| `STATUS.md` | драйвер | где цикл сейчас |
| `BLOCKED.txt` | драйвер | задачи, упавшие трижды |
| `logs/runs.csv` | драйвер | строка на проход: время, цена, ходы, ворота |
| `logs/iter-NNN.json` | драйвер | полный ответ `claude` по проходу |
| `scratch/` | подагенты | черновые скрипты счёта |

## Как смотреть, что происходит

```
Get-Content loop\STATUS.md
Get-Content loop\JOURNAL.md -Tail 40
Import-Csv loop\logs\runs.csv | Format-Table
git log --oneline test_loop
```

## Ограничения

1. Цикл не пушит. Ветка `test_loop` остаётся локальной, и это намеренно.
2. Сеть агенту закрыта по умолчанию. Текст из интернета это чужие указания, а
   агент работает без надзора.
3. Бюджет `-Hours` считает время работы `claude`, а не время ворот. Ворота
   добавляют примерно три минуты на проход.
4. Драйвер верит отметке `[x]` в плане. Итерация может отметить задачу, не
   сделав её. От этого защищают ворота и журнал, а не драйвер.
