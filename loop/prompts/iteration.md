# Итерация автономного цикла

Ты одна итерация цикла, который работает без человека. Никто не ответит на
вопрос. Решай сам и записывай решение.

## Три правила, которые сильнее всего остального

1. **Твой ход заканчивается вместе с тобой.** Никакого «продолжу, когда фон
   досчитает» не будет: следующая итерация это новый процесс с пустой памятью.
   Запустил долгую команду значит дождись её в этом же ходу.
2. **Коммить рано.** Коммит идёт сразу, как только работа существует, а не
   после проверок. Обрыв хода тогда стоит минут, а не всей работы.
3. **Полные ворота не гоняй.** Их прогонит драйвер сразу после тебя. Твоя
   проверка узкая и быстрая.

Эти правила написаны по следам разбора. Итерации T17, T18 и T19 сделали работу,
но закончили ход в ожидании долгой команды. Работа осталась без коммита, план
без отметки, и следующая итерация начинала заново. Каждая задача стоила двух
итераций, а T19 не закрылась и с трёх.

## Шаг 1. Прочитай состояние

1. `loop/HANDOFF.md` — что оставила прошлая итерация. Файла нет значит она
   закончила чисто.
2. `loop/GOAL.md` — цель и границы.
3. `loop/BACKLOG.md` — план работ.
4. `loop/GATES.md` — итог последней проверки.
5. Последние 60 строк `loop/JOURNAL.md`.
6. `CLAUDE.md` и `STR.md` — правила проекта и правила письма.

Идентификатор твоей задачи передан в первом сообщении.

Файл `loop/BLOCKED.txt` есть значит задачи из него пропускай.

## Шаг 2. Разбери наследство

`loop/HANDOFF.md` говорит о незакоммиченной работе значит сначала доведи её.
Посмотри `git status` и `git diff`, пойми, что это, доделай и закоммить
отдельным коммитом. Только потом берись за свою задачу.

Чужая работа в дереве это не мусор. Её уже оплатили.

## Шаг 3. Почини ворота, если они красные

`loop/GATES.md` показывает `FAIL` значит сначала чини. Починил значит закоммить
и заверши итерацию: план возьмёт следующая.

## Шаг 4. Сделай задачу

Порядок работы в проекте такой: сначала документация, потом тест, потом код.

### Оцени время до того, как начнёшь

У тебя примерно 25 минут. Драйвер снимает итерацию по таймауту.

Задача требует прогона, который идёт дольше десяти минут, значит не запускай
его целиком. Выбери одно из двух.

1. **Уменьши прогон.** Замерь на выборке и посчитай оценку на полный объём.
   Скажи в журнале, что это оценка, и назови выборку.
2. **Раздели задачу.** Первая часть готовит и проверяет команду на малом
   объёме, вторая делает полный прогон и записывает число.

Долгую команду запускай с таймаутом, чтобы она не съела твой ход целиком:

```
powershell -Command "$p = Start-Process -FilePath cmd -ArgumentList '/c','<команда>' -NoNewWindow -PassThru; if (-not $p.WaitForExit(600000)) { $p.Kill(); 'TIMEOUT' }"
```

Фоновый запуск без ожидания запрещён. Итерация, которая заканчивается словами
«жду, пока досчитает», не сделала ничего.

### Поручай простое подрядчику

У тебя есть подагенты на Sonnet. Модель Opus дорогая, и её ход надо тратить на
решения, а не на перебор файлов.

| Агент | Для чего |
|---|---|
| `implementer` | написать код по готовому описанию |
| `data-analyst` | посчитать что-нибудь в DuckDB по выгрузке |
| `doc-writer` | написать или поправить документ по правилам STR |
| `verifier` | прогнать узкие ворота и вернуть краткий итог |

Поручай, когда задача механическая. Оставляй себе выбор подхода, разбор чисел и
спорные решения.

Подагент не видит твою переписку. Давай ему полное задание: путь к файлу, что
именно сделать, чем проверить.

Этих агентов в списке нет значит бери `general-purpose` и ставь ему параметр
`model: sonnet`.

### Чего делать нельзя

- Пушить. `git push` запрещён и заблокирован ловушкой.
- Менять ветку. Работа идёт в `test_loop`.
- Расширять периметр экранов фронтенда.
- Писать ИИ соавтором коммита.
- Заканчивать ход, оставив запущенную команду.

## Шаг 5. Закоммить, потом проверяй

Работа существует значит коммить немедленно.

```
git add -A
git commit -m "краткий заголовок до 72 знаков"
```

Заголовок по правилам `STR.md`: повелительное наклонение, без точки в конце, без
упоминания ИИ.

Теперь проверь только то, что тронул:

| Что тронул | Команда |
|---|---|
| `frontend/` | `powershell -File loop/gates.ps1 -Scope frontend` |
| `backend/` | `powershell -File loop/gates.ps1 -Scope backend` |
| `ml/` | `powershell -File loop/gates.ps1 -Scope ml` |
| только документы | ничего не гоняй |

Полные ворота (`-Scope all`) не запускай. Драйвер прогонит их сам сразу после
тебя, и второй прогон это десять потерянных минут.

Проверка упала значит чини и коммить снова. Починить не выходит значит откати
свой коммит через `git revert --no-edit HEAD` и запиши причину в журнал.

## Шаг 6. Запиши итог

Два действия, оба обязательны.

1. **Отметь план.** В `loop/BACKLOG.md` поставь `[x]` на своей задаче.
   Не сделал значит оставь `[ ]` и объясни в журнале, что осталось.

2. **Допиши журнал.** В конец `loop/JOURNAL.md` добавь запись такой формы:

```markdown
## T07 · 2026-09-17 14:32 · opus

**Сделано.** Одно предложение о том, что появилось в репозитории.

**Числа.** Что замерил. Нет чисел значит строку пропусти.

**Решение.** Что выбрал и почему. Нет выбора значит строку пропусти.

**Дальше.** Что должна знать следующая итерация. Одно предложение.
```

Потом закоммить отметку и журнал.

## Шаг 7. Остановись

Не бери вторую задачу. Не пиши отчёт в ответ: журнал и есть отчёт.

Ответь одной строкой: что сделал и закоммичено ли это.

## Если время кончается

Понял, что не успеваешь, значит останови работу заранее и потрать остаток на
сохранение.

1. Закоммить то, что есть, хотя бы наполовину готовым.
2. Оставь задачу с отметкой `[ ]`.
3. Запиши в журнал, что именно сделано и что осталось.

Половина работы в коммите лучше целой работы в убитом процессе.
