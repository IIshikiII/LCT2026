# Итерация автономного цикла

Ты одна итерация цикла, который работает без человека. Никто не ответит на
вопрос. Решай сам и записывай решение.

## Шаг 1. Прочитай состояние

Прочитай в этом порядке:

1. `loop/GOAL.md` — цель и границы.
2. `loop/BACKLOG.md` — план работ.
3. `loop/GATES.md` — итог последней проверки. Файла нет значит проверка не шла.
4. Последние 60 строк `loop/JOURNAL.md` — что было в прошлых итерациях.
5. `CLAUDE.md` и `STE.md` — правила проекта и правила письма.

Идентификатор твоей задачи передан в первом сообщении. Найди строку с этим
идентификатором в `loop/BACKLOG.md`. Это твоя единственная задача.

Если файл `loop/BLOCKED.txt` есть, задачи из него пропускай: они уже трижды
упали.

## Шаг 2. Почини ворота, если они красные

`loop/GATES.md` показывает `FAIL` значит сначала чини. Задача из плана ждёт.
Починил значит закоммить и заверши итерацию: следующая возьмёт план.

## Шаг 3. Сделай задачу

Порядок работы в проекте такой: сначала документация, потом тест, потом код.

Задача оказалась больше одной итерации значит разбей её. Замени строку в
`loop/BACKLOG.md` на две с номерами вида `T07a` и `T07b`, сделай первую.
Разбивать лучше, чем оставлять задачу недоделанной.

Задача оказалась ошибочной значит отметь её `[-]`, объясни причину в журнале и
поставь взамен правильную.

### Поручай простое подрядчику

У тебя есть подагенты на Sonnet. Модель Opus дорогая, и её ход надо тратить на
решения, а не на перебор файлов.

| Агент | Для чего |
|---|---|
| `implementer` | написать код по готовому описанию |
| `data-analyst` | посчитать что-нибудь в DuckDB по выгрузке |
| `doc-writer` | написать или поправить документ по правилам STE |
| `verifier` | прогнать ворота и вернуть краткий итог |

Поручай, когда задача механическая: перенести признаки, написать тест по
образцу, обновить документ. Оставляй себе выбор подхода, разбор чисел и спорные
решения.

Подагент не видит твою переписку. Давай ему полное задание: путь к файлу, что
именно сделать, чем проверить.

Этих агентов в списке нет значит бери `general-purpose` и ставь ему параметр
`model: sonnet`. Задание тогда пиши подробнее: своего описания у такого агента
нет.

### Чего делать нельзя

- Пушить. `git push` запрещён и заблокирован ловушкой.
- Менять ветку. Работа идёт в `test_loop`.
- Трогать `main` и `backend`.
- Удалять `raw_task/`, `eda/out/`, `.venv`, `node_modules`.
- Расширять периметр экранов фронтенда.
- Писать ИИ соавтором коммита.
- Оставлять ворота красными.

## Шаг 4. Проверь

Прогони ворота:

```
powershell -ExecutionPolicy Bypass -File loop/gates.ps1
```

Ворота красные значит чини, пока не позеленеют. Починить не выходит значит
откати свою правку через `git checkout -- <файл>` и запиши в журнал причину.
Красные ворота в коммите хуже, чем невыполненная задача.

## Шаг 5. Запиши итог

Три действия, все обязательны.

1. **Отметь план.** В `loop/BACKLOG.md` поставь `[x]` на своей задаче.
   Не сделал значит оставь `[ ]` и объясни в журнале.

2. **Допиши журнал.** В конец `loop/JOURNAL.md` добавь запись такой формы:

```markdown
## T07 · 2026-09-17 14:32 · opus

**Сделано.** Одно предложение о том, что появилось в репозитории.

**Числа.** Что замерил. Нет чисел значит строку пропусти.

**Решение.** Что выбрал и почему. Нет выбора значит строку пропусти.

**Дальше.** Что должна знать следующая итерация. Одно предложение.
```

3. **Закоммить.** Всё, что сделал, одним коммитом.

```
git add -A
git commit -m "краткий заголовок до 72 знаков"
```

Заголовок по правилам `STE.md`: повелительное наклонение, без точки в конце, без
упоминания ИИ. Тело только тогда, когда заголовок не вмещает «почему».

## Шаг 6. Остановись

Сделал три действия шага 5 значит итерация закончена. Не бери вторую задачу.
Не пиши отчёт в ответ: журнал и есть отчёт.
