# Итерация починки

Ворота красные. План работ ждёт. Твоя единственная задача сделать их зелёными.

## Шаг 1. Прочитай

1. `loop/GATES.md` — что именно упало.
2. Последние 40 строк `loop/JOURNAL.md` — что делала прошлая итерация.
3. `git log --oneline -5` и `git show --stat HEAD` — что изменилось последним.

## Шаг 2. Найди причину

Правило одно: чини причину, а не признак.

Тест падает значит выясни, кто прав: тест или код. Тест описывает требование
значит правь код. Тест устарел после осознанной смены контракта значит правь
тест и напиши в журнале, какое требование изменилось и почему.

Не удаляй тест, чтобы ворота позеленели. Не ставь `skip`. Не ослабляй
утверждение до бессмысленного.

## Шаг 3. Откат как законный выход

Причину найти не удалось значит откати последний коммит:

```
git revert --no-edit HEAD
```

Откат лучше, чем полдня красных ворот. Запиши в журнал, что откатил и почему.
Верни задачу в `loop/BACKLOG.md` отметкой `[ ]`.

## Шаг 4. Проверь и запиши

Прогони только ту область, где было падение. Имя упавших ворот в `GATES.md`
называет её прямо.

```
powershell -ExecutionPolicy Bypass -File loop/gates.ps1 -Scope backend
```

Отчёт говорит `slow tests skipped` значит падение могло быть в медленном
тесте. Тогда добавь `-IncludeSlow`, но только для нужной области.

Полные ворота (`-Scope all`) не запускай: драйвер прогонит их сразу после тебя.

Ход заканчивать с запущенной командой нельзя. Следующая итерация это новый
процесс, и он о твоём фоне ничего не узнает.

Ворота зелёные значит допиши журнал записью такой формы:

```markdown
## REPAIR · 2026-09-17 15:10 · sonnet

**Упало.** Что именно.

**Причина.** Одно предложение.

**Починка.** Что сделал.

**Дальше.** Что должна знать следующая итерация.
```

Потом закоммить:

```
git add -A
git commit -m "починить <что>"
```

Остановись. Задачу из плана не бери.
