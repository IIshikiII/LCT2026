# Цель автономного цикла

Этот файл читает каждая итерация. Правь его, чтобы сменить цель.

## Что сделать

Довести направление `UNAUTHORIZED_ACCESS` (несанкционированный доступ) до
сквозного рабочего состояния: данные, метка, признаки, модель, объяснение через
SHAP, плагин бэкенда, API, экран диспетчера.

Готово значит вот что.

1. Модель обучена на выгрузке `eda/out/events.parquet` и бьёт наивную планку
   21,8 % (см. `hackathon-gap-analysis.md` §A4).
2. Каждый прогноз объясняется SHAP. Вклад признаков попадает в блок `factors`
   карточки диспетчера.
3. Плагин `backend/app/ml/plugins/unauthorized_access.py` реализует протокол
   `app/ml/protocol.py` целиком.
4. Конвейер пишет прогнозы в таблицу `prediction`, API их отдаёт.
5. Фронтенд рисует объяснение. Моки и настоящий API дают одинаковую форму
   ответа.
6. Все ворота зелёные: `loop/gates.ps1`.

## Чего не делать

- Не трогать карту объектов.
- Не расширять периметр экранов. Их ровно четыре.
- Не заводить ручку API под каждую кнопку.
- Не пушить в удалённый репозиторий. Никогда.
- Не менять `main` и `backend`. Работа идёт только в ветке `test_loop`.
- Не ломать другие направления. `FIRE_RISK`, `SENSOR_FAILURE` и `FLOOD_RISK`
  обязаны работать как раньше.

## Правила, которые сильнее цели

1. `CLAUDE.md` в корне. Особенно шесть архитектурных правил фронтенда.
2. `STR.md` для русского текста, `STE.md` для английского.
3. Порядок работы: сначала документация, потом тест, потом код.
4. Правка контракта API без правки `frontend/docs/02-api-contract.md` и
   мок-хендлера в том же коммите считается незавершённой.
5. Коммит не указывает ИИ соавтором.

## Докер доступен

Демон Docker запущен. Пользуйся им: он даёт настоящую базу, настоящий API и
реестр моделей вместо заглушек. Файл сборки лежит в `backend/docker-compose.yml`.

Postgres уже поднят и здоров. Preflight поднимает его сам, поэтому проверять
перед работой не нужно.

| Служба | Профиль | Порт | Что это |
|---|---|---|---|
| `db` | основной | 5432 | Postgres 16, уже работает |
| `api` | основной | 8000 | FastAPI, требует сборки образа |
| `mlflow` | основной | 5000 | реестр версий моделей, требует сборки |
| `pipeline` | `tools` | нет | разовые команды конвейера |
| `research` | `tools` | 8888 | JupyterLab, только петлевой интерфейс |
| `dev` | `tools` | нет | тесты и линт в образе |

Базы созданы: `arm` рабочая, `arm_test` для тестов, `mlflow` для реестра.

Строка соединения с хоста:

```
postgresql+psycopg://arm:arm@127.0.0.1:5432/arm
```

Адрес, а не имя `localhost`. На Windows имя разрешается сначала в IPv6, и
подключение ждёт таймаута системы 130 секунд. Это умолчание в
`backend/app/config.py`, менять его не надо.

Порты служб опубликованы только на петлевом интерфейсе. Открыть наружу можно
переменной `BIND_HOST=0.0.0.0`, но для работы цикла это не нужно.

Команды из папки `backend`:

```
docker compose ps
docker compose up -d db
docker compose up -d api
docker compose run --rm pipeline uv run --no-sync python -m app.cli migrate
docker compose logs --tail 50 api
docker compose restart db
```

Правила пользования.

1. **Сборка образа стоит минут.** `docker compose up -d api` в первый раз
   собирает образ. Заложи это в оценку итерации, а не удивляйся таймауту.
2. **Ворота гоняй локальными средами, а не службой `dev`.** Локально это
   секунды, в образе минуты. Служба `dev` нужна тогда, когда надо повторить
   поведение образа.
3. **Том базы сносить нельзя.** `docker compose down -v` заблокирован ловушкой.
   Нужен чистый лист значит чисти таблицы запросом или применяй миграции заново.
4. **Служба `api` монтирует `./app` только на чтение.** Правка кода на хосте
   видна внутри, но перезапуск службы нужен: `docker compose restart api`.

## Известные ловушки

1. **Параллельный join в DuckDB отдаёт строки в произвольном порядке.** Он
   меняется от запуска к запуску. Любой запрос, результат которого идёт в
   модель, обязан иметь `ORDER BY`.
2. **Артефакт миграции.** Объект 5343 за 2020 и 2021 годы даёт 73 % всех
   записей «Неисправен». Исключается один объект за два года, а не годы целиком.
3. **Пачки тревог.** У 141 457 моментов на канал приходится две тревоги в одну
   секунду. Событием считать момент, а не строку.
4. **Общий сбой.** В 709 моментов тревожат от 21 до 100 каналов сразу. Такой
   момент весит как одно наблюдение.
5. **Утечка по времени.** Признак не имеет права смотреть после `ctx.at`.
   Разбиение выборки только по времени.
